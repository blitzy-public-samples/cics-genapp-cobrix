# Synthetic CLASS-scale General Liability corpus

Generated by `generate_synthetic_class.py` from IBM's GenApp COBOL sample
(https://github.com/cicsdev/cics-genapp) to approximate the scale of
Travelers' CLASS system for a data modernization demo.

## What's here

- `programs/<coverage-part>/*.cbl` — **5,000** COBOL programs
- `copybooks/<coverage-part>/*.cpy` — **20,000** copybooks
- `manifest_programs.csv` — every program: coverage part, state, operation,
  layer, which program it LINKs to, which copybook it COPYs
- `manifest_copybooks.csv` — every copybook: coverage part, state, kind

Both counts and cross-references were verified: every `links_to` and
`copybooks_used` value in the program manifest resolves to a real row in
the other manifest, and every program/copybook name is exactly 8
characters (the traditional mainframe program/DD-name ceiling).

## How it's structured

GenApp's three-layer pattern is preserved exactly:

```
business logic (L)  --EXEC CICS LINK-->  DB2 access (D)  --EXEC CICS LINK-->  VSAM access (V)
```

- **L** validates the commarea length, then LINKs to D.
- **D** runs `EXEC SQL INSERT/UPDATE/DELETE/SELECT` against a coverage-part
  table, then (for ADD/UPDATE/DELETE) LINKs to V to keep a VSAM KSDS in
  sync — same as GenApp's `LGAPDB01` linking to `LGAPVS01`.
- **V** runs `EXEC CICS WRITE/REWRITE/DELETE/READ FILE` against a KSDS.

This is multiplied across **12 synthetic General Liability coverage
parts** (Premises & Operations, Products & Completed Operations, Personal
& Advertising Injury, Medical Payments, Fire Legal Liability, Employee
Benefits Liability, Liquor Liability, Umbrella/Excess, Contractual
Liability, Limited Pollution, Owners & Contractors Protective, Hired &
Non-Owned Auto) **x 51 states x 5 operations (Add/Inquire/Update/Delete/
Rate) x 3 layers**, with a "generation" sequence number that lets the
generator keep producing 01/02/03... variants of the same combination —
mirroring how real legacy shops accumulate near-duplicate programs across
decades of state-by-state, coverage-by-coverage changes.

Each coverage part has its own field list (limits, deductibles, class
codes, exposure bases, etc.), so copybooks aren't identical clones with
different names — they carry genuinely different rating/underwriting
data, the same way real ISO CGL coverage parts do.

## What this is not

This is not a compiled, runnable CICS/DB2 application, and it is not real
CLASS code (which is proprietary). It is a structurally realistic,
referentially consistent stand-in sized to match the *scale* Travelers
described (5,000+ programs, 20,000+ copybooks) — useful for exercising
ingestion tooling (copybook parsers, dependency/impact-analysis scripts,
Databricks Autoloader configs) before pointing that tooling at anything
real.

## Regenerating at a different scale

```
python3 generate_synthetic_class.py --out-dir ./synthetic_class \
    --num-programs 5000 --num-copybooks 20000
```

Any counts work — the generator cycles through the
coverage-part x state x operation x layer combinations and adds
"generation" suffixes as needed to hit whatever total you ask for.
